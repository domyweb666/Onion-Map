# 洋蔥：功能增刪與技術路線

2026-11-07，看完原型、做完 iOS 包裝之後的想法。先講三個結論：

1. 技術路線走 Capacitor：現有網頁原封不動包進原生殼，定位換成原生背景定位。等到要做鎖定畫面的 Live Activity、Widget、Apple Watch，或 WebView 裡的地圖在舊 iPhone 上撐不住，再談 SwiftUI 重寫。
2. 「踏進異世界，手機幫我畫地圖」做得到，但要先講清楚手機畫得出什麼。GPS 給的是一條線，畫不出你沒走到的河岸長什麼樣。可行的版本是三層：地貌的形狀跟現成資料借，但不顯示任何現成地名；哪裡被揭露由你走出來；名字、圖示、日記由你寫。每個人的圖都長得不一樣，異世界的感覺從這裡來。
3. 功能先把「背景記錄、資料不會丟、手札畫風」做到底，再談成就、統計、社群。模擬模式藏起來，飛行判定要能撤銷。

## 1. 原型現在是什麼

一張羊皮紙，走過的地方才看得到底下的地圖。位置落在 H3 的六角格（解析度 12，一格邊長約 10 公尺），步行揭露半徑 30 公尺，搭車 14 公尺的窄帶，超過 330 km/h 又跳了 50 公里以上就當作飛機，畫一條紅色虛線航線。去過越多次的格子顏色越深。縮小到全國時格子看不見，改畫墨線軌跡。桌上測試用模擬模式點地圖。資料存瀏覽器的 localStorage，可下載 JSON 備份。

引擎（`createEngine`）已經獨立成純邏輯，不碰畫面，這是原型最好的設計決定，搬去哪個平台都能帶著走。

網頁版的死穴寫在它自己的畫面上：Safari 不在前景就不記錄。這次 iOS 包裝就是為了這一條。

## 2. 技術路線

### 2.1 四條路

| | 改動量 | 背景定位 | 沒有 Mac 能不能做 | 原生能力 |
|---|---|---|---|---|
| PWA（加到主畫面） | 零 | 做不到，iOS 不給網頁背景定位 | 能 | 無 |
| Capacitor（現在這條） | 小：平台分流約 100 行 | 原生 plugin，可以 | 能，雲端 Mac 編譯 | 要什麼補什麼，寫 Swift plugin |
| Expo / React Native | 大：介面重寫，引擎與地圖樣式可搬 | 可以 | 能，EAS Build | 中 |
| SwiftUI + MapLibre Native | 全部重寫 | 最好 | 幾乎不能，要 Xcode | 最好 |

### 2.2 為什麼是 Capacitor

原型的三樣東西都能原樣帶走：引擎是純 JS，地圖樣式是 MapLibre 的 style JSON，畫面是 HTML。要重寫的只有一件事，定位從 `navigator.geolocation` 換成原生 plugin，這次已經換好。

沒有 Mac 這件事，Capacitor 的解法最成熟：Xcode 專案可以在 Windows 上產生（已實測），編譯交給 GitHub Actions 或 Codemagic 的雲端 Mac，裝機走 AltStore 或 TestFlight。細節在 `docs/iOS建置說明.md`。

代價有兩個。地圖跑在 WKWebView 裡，MapLibre GL JS 在 iPhone 11 以前的機器縮放時可能掉幀，要真機看。原生的介面元件（分享面板、權限視窗）有，但自己的畫面全是 HTML，要原生手感得自己刻。

### 2.3 什麼時候該換路線

碰到下面任何一條再換，沒碰到不要換：

- 要做鎖定畫面的 Live Activity（「記錄中・今天 3.2 km」）、主畫面 Widget、Apple Watch。這些 Capacitor 要另外寫 Swift，寫到一定量不如直接原生
- 真機上地圖掉幀，而且調過圖層數量還是不行
- 要用 CoreMotion 的活動辨識（走路／跑步／騎車／搭車）取代速度判定。這是 Swift plugin 能做的事，不一定要換路線，但會是第一個自己寫的原生模組

### 2.4 這次做好的與還沒驗的

做好的：`ios/` Xcode 專案、背景定位、紀錄存進 app 的 Documents 資料夾（跟著 iCloud 手機備份）、匯出走 iOS 分享面板、上次在記錄的話開 app 自動續錄、羊皮紙 icon 與啟動畫面、GitHub Actions 的編譯檢查與未簽署 IPA、Codemagic 的 TestFlight 流程。

還沒驗的：整個 iOS 專案沒有在 Mac 上編譯過（Windows 做不到），第一次 push 上去 CI 大概會有東西要修。背景記錄的實際行為、耗電、系統殺掉 app 後的狀況，都要真機走一趟才知道。

## 3. 「踏進異世界，手機幫我畫地圖」可不可行

### 3.1 手機真的能感測到什麼

| 感測器 | 給你什麼 | 畫得出什麼 |
|---|---|---|
| GPS | 位置、速度、高度 | 一條線、線周圍的一個圓 |
| 氣壓計 | 海拔變化 | 路線的上坡下坡 |
| CoreMotion | 走／跑／騎／車／靜止 | 不同筆觸的線，判定比速度準，也省電 |
| 羅盤 | 面向 | 探險家的朝向箭頭 |
| 相機、LiDAR | 5 公尺內的形狀 | 畫不了街區，範圍太短 |
| Wi-Fi、藍牙密度 | 附近人煙 | 「聚落」的粗略判斷，隱私與系統限制多，不建議 |

結論：感測器畫得出「你的軌跡與高低」，畫不出「你沒走到的地方長什麼樣」。純靠感測器，城市裡走一個月得到的是一團線，沒有河、沒有街區、沒有山的輪廓。要有「地圖」，形狀要跟現成資料借。

### 3.2 可行的定義：三層

幾何層，借來的。道路、水域、建築、森林來自 OpenStreetMap（現在就在用），山的形狀來自高程資料（AWS 的 Terrain Tiles 免費、不用金鑰）。這一層是「異世界本來就在那裡」的地貌。

揭露層，走出來的。現在的 H3 格子與迷霧。沒走到的地方只有羊皮紙，頂多一點極淡的海岸線與國界讓你知道自己在哪，原型已經這樣做。

意義層，你寫的。預設不顯示 OSM 的任何地名。地名由你取，圖示由你選，日記由你寫。走到一條河，地圖上只有一條墨色的水，你給它叫「灰狼河」它才叫灰狼河。這一層才是「自己搭」的部分，也是跟世界迷霧最大的差別。

三層疊起來，每個人的圖都不一樣：同一條台北的河，在我的圖上叫一個名字，在你的圖上叫另一個名字，而我們都沒看過「基隆河」三個字。

### 3.3 純手札模式

把幾何層整個關掉的開關：只剩你的墨線、揭露的格子、地形陰影、你的註記。這是最像「異世界」的版本。城市裡會變成一團線，山上、鄉下、旅行時很好看。做成切換，不要二選一。

### 3.4 感測器真的能貢獻的幾個小東西

- 走過越多次墨色越深。原型的 freq 層已經在做，換個說法叫「踏實的路」
- 海拔起伏畫成路邊的小山丘筆觸。背景定位 plugin 已經回傳 altitude，不用再接氣壓計
- 停留超過 N 分鐘的地方自動變成「營地」候選，跳出來問你要不要命名。這是意義層最自然的入口，你不用主動長按
- 走路、搭車、搭船的線用不同筆觸：實線、虛線、波浪線

## 4. 探險家手札畫風怎麼落地

### 4.1 MapLibre 能直接做的，不用換引擎

| 元素 | 作法 |
|---|---|
| 紙 | 真的掃描紙紋貼圖。原型是程式亂數點，可以更像紙 |
| 道路 | 雙線墨筆：同一條路畫兩條 line-offset 的細線，加輕微 dasharray 製造斷筆 |
| 建築 | 斜線 hatch 的 fill-pattern，外框墨線 |
| 水 | 墨水暈染色，疊波紋 fill-pattern |
| 森林 | 樹形 sprite 的 fill-pattern，一叢一叢 |
| 山 | 高程 hillshade 調成褐色墨影，加 maplibre-contour 畫等高線，就有手札的筆觸感 |
| 地名 | 手寫字型。繁中可用辰宇落雁體或清松手寫體，兩套都是 OFL 授權，轉成 MapLibre 的 glyph pbf 放 GitHub Pages 就能用 |
| 迷霧邊緣 | 原型是模糊線，可疊一層撕紙紋理的 line-pattern |
| 裝飾 | 羅盤玫瑰、標題框、比例尺用 HTML 疊在地圖上；海上的迷霧放海怪 |

這些都是 style JSON 與 sprite 圖的事，引擎不用動。手寫字型是第一個該做的，一換字型整張圖的氣質就變了。

### 4.2 要注意的

圖磚來源。OpenFreeMap 免費、不限次數、不用金鑰，但是一個人維運、靠捐款。正式上架要有備案：MapTiler 或 Stadia 付費，或用 Protomaps 自己切 PMTiles 放自己的空間。原型的 style 是 OpenMapTiles 的 schema，換來源只改一個 URL。

離線。探險家會走到沒訊號的地方。PMTiles 可以把台灣切成一個檔（看 zoom，幾百 MB 起跳，要實際切一次才知道），放 app 裡或讓使用者下載。沒網路時至少還有地貌，不會只剩羊皮紙。

字型授權。OFL 允許轉格式散佈，保留名稱不能拿來叫改過的版本。

## 5. 功能：加什麼、強化什麼、藏什麼

### 5.1 先定義每天的迴圈

出門 → 回來看地圖多了什麼 → 幫新地方取名字、寫一行 → 把那一頁分享出去。

所有功能都要能掛在這條迴圈上，掛不上的先不做。

### 5.2 P0，沒有就不是產品

1. 背景記錄。這次做了，要真機驗
2. 資料不會丟。這次把紀錄存進 Documents 資料夾，跟著 iCloud 手機備份走。下一步是 iCloud Drive 同步或 CloudKit，換手機、重裝都不怕
3. 資料模型改版。原型的軌跡點上限 6 萬點，整包 JSON 每次重寫。背景記錄一天就撞牆，而且格子多了之後每次存檔都是幾 MB。改成「格子索引一份、軌跡檔逐日一份」，只重寫當天的。這件事在手札畫風之前，因為畫風做再好，資料被砍掉就白做
4. 手札畫風第一版：手寫字型、道路墨線、建築 hatch、地形陰影。四樣做完就能拿出去給人看

### 5.3 P1，讓它變成「我的」地圖

5. 命名與圖示。長按地圖，或系統抓到停留點時問你，取名、選圖示（先做 30 個手繪 sprite）、寫一行字
6. 預設隱藏 OSM 地名。開關叫「測繪師模式」才顯示現成地名
7. 手札頁。每天或每趟自動排一頁：路線簡圖、公里數、新揭露面積、新命名的地方，存成圖片。對做內容的人來說這就是傳播口，一張圖貼上去別人就想要
8. 匯入。GPX、Google 時間軸（手機版匯出的 Timeline.json）。很多人手上有好幾年的位置紀錄，一次進來地圖就不是空的

### 5.4 P2

9. 純手札模式開關
10. 統計：縣市、鄉鎮的揭露百分比，用 OSM 的行政邊界算
11. 發現印章：第一次碰到河、海岸、山頂、公園自動蓋一個章在手札頁
12. Widget、Live Activity。要原生，到時候決定寫 Swift plugin 還是換路線

### 5.5 藏起來或拿掉

模擬模式。留在程式碼裡當測試工具，正式版藏起來（例如「資料」頁長按才出現）。給使用者看會混淆，審核也可能當成造假位置的功能。

飛行自動判定。保留，但畫上去之前問一句「這段是搭飛機嗎？」，而且要能刪。GPS 跳點被當成飛機、畫一條紅線橫跨半個台灣，是永久性的污染，原型現在沒有任何撤銷。

汽車的 14 公尺窄帶揭露。搭車算不算「探索」是設計題。手札的邏輯是「走過的路」畫成墨線，不一定要揭露面積。先留著，等真機跑幾趟看圖再決定。

頂欄的「航線幾段」。放到統計頁，頂欄只留面積與公里，少一個數字版面乾淨很多。

### 5.6 跟世界迷霧的關係

世界迷霧（Fog of World）NT$990 買斷，App Store 台灣 4.8 星、9,551 則評分，2012 年就有，功能很滿：等級、徽章、Widget、Siri 捷徑、路線編輯、多家雲端同步、GPX 與 KML 匯入。洋蔥比功能比不過它，能贏的是畫風、手札、命名這三件它沒有的事。它的迷霧是灰色遮罩蓋在一般地圖上，洋蔥的迷霧是羊皮紙。

## 6. 現有程式的隱患，真機前要知道

- 軌跡點上限與整包重寫，見 5.2 第 3 點
- 格子數量上十萬之後，每次 render 都把全部格子丟進 `cellsToMultiPolygon` 會卡。解法是用 H3 的 `compactCells` 把整塊合併成大格，或只算視窗內的格子
- app 在背景時 WebView 的 setTimeout 可能被延後。畫面不畫沒關係，存檔靠切到背景時立刻寫（這次做了），但系統直接殺掉 app 時最後 10 秒內的點會掉
- 系統殺掉 app 之後記錄不會自己醒來。目前的 plugin 沒有用 significant location change 喚醒 app，要的話補一小段 Swift
- App Store 審核：永遠允許的定位要在審核備註寫清楚用途，而且關掉記錄時狀態列的藍色膠囊要消失。這次 removeWatcher 會停掉 CLLocationManager，應該沒問題，要真機確認
- 第一次 CI 可能卡在 Xcode scheme 自動產生或 Swift 套件解析，這些在 Windows 上驗不了

## 7. 下一步的順序

1. push 這個分支，看 GitHub Actions 綠不綠。第一次要修的多半是 CI 本身
2. 用 AltStore 把未簽署 IPA 裝到手機，走 30 分鐘的路：背景有沒有畫、掉多少電、格子形狀對不對
3. 真機跑過之後決定資料模型改版與手札畫風第一版誰先
4. 要走你自己的 iOS UIUX 流程的話，從核心動作卡開始。核心動詞只有一個：揭露
