## 一、先決定四件事

多米決定，後面會照這個做。每項都附我的建議。

1. 1.0 要不要放「請 ChatGPT 畫」。建議 1.0 先藏起來，TestFlight 留著自己測。要有電腦、裝 Codex、開同一個 Wi-Fi 才用得到，審查員沒辦法試，一般使用者也多半過不了這關。藏起來還可以一起拿掉相機和區域網路兩個權限。迷霧、足跡、印章、四款框都不靠它
2. 要不要支援 iPad。建議只做 iPhone。現在專案設成兩種都支援，這樣商品頁就一定要交 13 吋 iPad 截圖，審查也會用 iPad 版面看。以後想加隨時能加，先上了 iPad 再拿掉，Apple 不收（這句是經驗，沒有重查）
3. 商店名稱。建議先在 App Store 搜「洋蔥」和「洋蔥地圖」。名稱整個 App Store 不能重複，「洋蔥」八成被用了，備案填「洋蔥地圖」。手機桌面上顯示的「洋蔥」不受影響
4. 上架地區。建議照準則 10-22，拿掉中國大陸，其他都開。洋蔥是地圖 app，中國大陸對地圖另有規定，更不用碰

## 二、Apple 後台（多米，順序不要換）

開發者帳號、發佈憑證、API 金鑰，前面幾個 app 都辦過，能沿用就沿用。

| 東西 | 要新做嗎 |
|---|---|
| Apple Distribution 憑證（`.p12` 和密碼） | 不用，整個帳號共用。檔案在電腦上，GitHub 的 secret 看不回來，要找原始檔 |
| Team ID | 不用 |
| App Store Connect API 金鑰（`.p8`、Key ID、Issuer ID） | 不用，團隊金鑰每個 app 都能用，角色 App Manager 就夠。`.p8` 找不到才重建一把 |
| App Group、兩個 App ID、兩個 profile、App 紀錄 | 要，下面四步 |

`.p12` 找不到，或憑證滿一年過期了，照 [iOS建置說明](iOS建置說明.md) 的 C 段第 1 步重做。一個帳號最多三張，先看後台還剩幾張。

金鑰、憑證、profile 一律放在 repo 外面的資料夾。這個 repo 是公開的。

### 1. 登記 App Group

1. 開 https://developer.apple.com/account/resources/identifiers/list
2. 按 +，選 App Groups，Continue
3. Description 填 `Onion Group`，Identifier 填 `group.org.domyweb.onion`
4. Continue，Register

### 2. 登記兩個 App ID

1. 同一頁按 +，選 App IDs，再選 App
2. Description 填 `Onion`，Bundle ID 選 Explicit，填 `org.domyweb.onion`
3. Capabilities 往下找 App Groups，打勾
4. Continue，Register
5. 回清單點進 `org.domyweb.onion`，App Groups 那列按 Configure，勾 `group.org.domyweb.onion`，Save
6. 再做一次：Description 填 `Onion Widget`，Bundle ID 填 `org.domyweb.onion.widget`，一樣勾 App Groups、選同一個 group

清單裡已經有 `org.domyweb.onion` 的話不用重建，從第 5 步開始。

背景定位、相機、即時動態都不用在這裡勾。

### 3. 做兩個 profile

1. 開 https://developer.apple.com/account/resources/profiles/list ，按 +
2. Distribution 底下選 App Store Connect
3. App ID 選 `org.domyweb.onion`，憑證選 `.p12` 的那一張
4. 名稱填 `Onion App Store`，下載，存成 `app.mobileprovision`
5. 再做一個：App ID 選 `org.domyweb.onion.widget`，名稱填 `Onion Widget App Store`，存成 `widget.mobileprovision`

之後只要動過 App ID 的能力，兩個 profile 都要重做、重放 secret。

### 4. 在 App Store Connect 建 App

1. 開 https://appstoreconnect.apple.com/apps ，按 +，新的 App
2. 平台勾 iOS
3. 名稱填第一節定的，主要語言選繁體中文
4. 套件識別碼選 `org.domyweb.onion`
5. SKU 填 `onion-ios`
6. 使用者存取權限選完整存取權限，建立

小工具不用另外建。

## 三、把 8 個 secret 放進 GitHub（多米）

名字跟人蔘修煉的不一樣，不要照抄。

到放金鑰的資料夾開 Git Bash，檔名換成自己的：

```bash
base64 -w0 ios_distribution.p12 | gh secret set IOS_P12_BASE64 -R domyweb666/Onion-Map
```

```bash
base64 -w0 app.mobileprovision | gh secret set IOS_PROFILE_BASE64 -R domyweb666/Onion-Map
```

```bash
base64 -w0 widget.mobileprovision | gh secret set IOS_WIDGET_PROFILE_BASE64 -R domyweb666/Onion-Map
```

```bash
gh secret set ASC_PRIVATE_KEY -R domyweb666/Onion-Map < AuthKey_你的KeyID.p8
```

剩下四個短的，到 https://github.com/domyweb666/Onion-Map/settings/secrets/actions 按 New repository secret 一個一個貼：

| 名字 | 貼什麼 |
|---|---|
| `IOS_P12_PASSWORD` | `.p12` 的密碼 |
| `APPLE_TEAM_ID` | developer.apple.com › Membership details 的 Team ID，10 碼 |
| `ASC_KEY_ID` | API 金鑰的 Key ID |
| `ASC_ISSUER_ID` | 同一頁上方的 Issuer ID |

放完檢查，應該列出 8 個名字：

```bash
gh secret list -R domyweb666/Onion-Map
```

`ASC_PRIVATE_KEY` 放 `.p8` 的原文。換行掉了、或放成 base64，`ios/ci/asc_key.mjs` 都會還原。還原不了就改用 `ASC_KEY_P8_BASE64`，那個是備用的，可以不放。

## 四、送第一版上 TestFlight

1. 觸發（AI 可以跑，多米先說可以）：

   ```bash
   gh workflow run ios.yml -R domyweb666/Onion-Map --ref paint-cli -f testflight=true
   ```

   `main` 還沒有這個檔，Actions 頁看不到 Run workflow 按鈕，從指令觸發就好。2026-11-14、11-15 用同樣的方法從 `domy-ui` 分支觸發過編譯，有跑起來

2. 看進度：

   ```bash
   gh run list -R domyweb666/Onion-Map --workflow ios.yml -L 3
   ```

3. 「簽署並上傳 TestFlight」變綠，再等 Apple 處理。前面幾個 app 的紀錄是 5 到 15 分鐘
4. App Store Connect › 洋蔥 › TestFlight，看到 1.0 和 build 號，狀態不是「處理中」就好了

編譯前會先驗金鑰，也會問 App Store Connect 有沒有這個 App，不行一分鐘內就紅。2026-11-25 第一次成功，整趟約四分鐘。紅燈的原因對照在第十節。

## 五、設定 TestFlight

### 給自己測：內部測試（多米）

不用審查，處理完馬上能裝。

1. TestFlight 分頁，左邊「內部測試」按 +，群組名填 `內部`，勾「啟用自動分發」，建立
2. 進群組，按 + 加測試員，選自己的 Apple 帳號
3. iPhone 從 App Store 裝 TestFlight，用同一個 Apple 帳號登入
4. 之後每次上傳成功，手機會自己跳新版

內部最多 100 人，要先是 App Store Connect 的使用者，角色是帳號持有人、管理員、App 管理、開發者或行銷。朋友和讀者走外部。

### 給朋友測：外部測試（多米）

要先有一個內部群組。

1. TestFlight 分頁 › 測試資訊，填：
   - Beta 版 App 說明，必填
   - 意見回饋電子郵件
   - 聯絡資訊。姓名、電話、信箱只填在這裡，不要寫進 repo
2. 左邊「外部測試」按 +，群組名填 `試玩`，建立
3. 進群組，加入 build，選 1.0 的那一版
4. 填「測試內容」，寫這版要大家試什麼
5. 按提交審查。第一個 build 要完整審查，同一版本後面的 build 不一定要再完整審一次。同一個版本一次只能有一個 build 在審，24 小時最多送 6 個
6. 過了之後加人，有兩種：
   - 電子郵件：一個一個邀請，最多 10,000 人
   - 公開連結：誰有連結都能裝，人數上限可以設 1 到 10,000。建議先設 20 人

每個 build 從上傳起算 90 天，過了就打不開，要再傳一版。

外部審查員也會真的打開 app。送外部之前，第七節標「外部測試前」的先補完。

### 測試說明可以直接用這段

> 洋蔥會把你走過的地方從黑霧裡露出來。
>
> 這版想請你試：
> 1. 打開 app，按記錄，出門走十分鐘，手機放口袋
> 2. 回來看地圖，走過的地方有沒有露出來，跟你走的路差多少
> 3. 長按地圖，幫一個地方取名字
> 4. 到製圖，選一款框，分享出去
> 5. 開飛航模式再打開一次
>
> 有怪的地方，在 TestFlight 截圖回報，寫你的 iPhone 型號和 iOS 版本。

## 八、App Store Connect 要填的

### 文字

| 欄位 | 上限 | 備註 |
|---|---|---|
| 名稱 | 30 字 | 第一節定的 |
| 副標題 | 30 字 | |
| 關鍵字 | 100 bytes | 中文一個字 3 bytes，大約 33 個字，用半形逗號隔開 |
| 宣傳文字 | 170 字 | 之後可以隨時改，不用送審 |
| 描述 | 4,000 字 | 不放價格、「▌」、Android 這類其他平台的名字 |
| 新功能 | 4,000 字 | 第一版不用填 |
| 支援網址、隱私權政策網址 | | 送審前用手機瀏覽器開一次 |
| 版權 | | 跟後台的賣家名稱一樣 |
| 審查備註 | 4,000 bytes | 草稿在下面 |

名稱、副標、關鍵字、描述叫 `domi-aso-control` 定，不要在這裡憑感覺寫。

類別建議主要選旅遊、次要選生活風格。不要選健康與健身，選了要多填一份醫療器材聲明。

### 截圖

- iPhone 交 1320 × 2868 那組，最多 10 張，JPG 或沒有透明的 PNG。蒜日子、人蔘修煉只交這組，後台都收。這次查 Apple 的規格頁，有一句寫至少要一張中尺寸，兩邊對不上，後台擋的話補一張 1206 × 2622
- iPad 只有支援 iPad 才要交，13 吋，2064 × 2752
- 拍的時候用假足跡，不要用真的軌跡，住家會露出來

### 年齡分級

照實填。1.0 沒有聊天、沒有使用者公開的內容、沒有網頁瀏覽、沒有購買，預期會是最低那一級。遇到沒看過的新題目停下來問多米。

### App 隱私（只能在網頁填，填完要按「發佈」，跳出來再按一次）

建議填「不收集資料」，理由：

- 沒有帳號、沒有分析套件、沒有自己的伺服器
- 足跡只存在手機和使用者自己的 iCloud 備份
- 看地圖會跟 OpenFreeMap 和 AWS 要圖磚，對方看得到 IP 和圖磚編號。OpenFreeMap 的一般紀錄不含 IP，錯誤紀錄可能有 IP 和網址，7 天刪掉

要多米點頭的一點：Apple 說的「收集」是資料傳出手機，開發者或合作夥伴留得比處理當下還久。OpenFreeMap 的錯誤紀錄算不算，沒有標準答案，AWS 那邊留多久沒查到。從嚴的填法是勾「大略位置」，用途選 App 功能、不連結身分、不追蹤，`PrivacyInfo.xcprivacy` 要跟著改。不管填哪個，隱私權政策都要寫到這兩家。

雲端畫圖上線那天整份要重填，照 [iOS建置說明](iOS建置說明.md) 的「雲端畫圖上線時要改的東西」。

### 其他

- 價格：免費也要設，選 0 元
- 內容版權：有用第三方內容（地圖資料），選有、並且有權使用
- 歐盟數位服務法的商家身分：上架歐盟一定要設。已經替別的 app 設過就看一下狀態
- 出口合規：`Info.plist` 寫了，應該不會問。問了就選只用系統內建的 HTTPS
- 付費 App 協議：1.0 沒有內購，不用

## 九、送審

### 錄影

審查員在室內，沒走路就看不到霧散開。第一次送審就附影片，不等 Apple 來要。

用最新 iOS 的 iPhone，裝送審那個 build，從主畫面點圖示開始，一鏡到底，錄到：

1. 打開 app，按記錄，跳定位權限，選允許
2. 出門走一小段，地圖露出來
3. 鎖螢幕，鎖定畫面的即時動態在走
4. 回到 app，足跡頁、印章
5. 製圖頁換框、分享
6. 設定頁：離線地圖、匯出備份、隱私權政策

不要從家門口開始錄，也不要為了錄影刪 app 重裝，足跡會不見。

### 給審查員的範例檔

做一個假軌跡的 GPX，放在 `domyweb.org/tools/onion/sample.gpx`，備註寫怎麼匯入。審查員不用走路就看得到功能。

### 審查備註草稿

假設 1.0 沒有 AI 畫圖、沒有內購。送之前每一句對一次程式，後面改了功能要跟著改。

```text
1. Video
The attached video was recorded on a physical iPhone running this build. It shows the location permission prompt, the map being revealed while walking, background recording with a Live Activity, and sharing a map.

2. Purpose
Onion Map is a personal travel map. The whole map starts covered in black fog. Places the user actually travels through are revealed. No account, no social features, no user-generated content visible to others, no in-app purchases, no ads, no analytics.

3. How to test without walking
Download the sample track: https://domyweb.org/tools/onion/sample.gpx
In the app: 設定 (Settings) > 匯入足跡或備份 (Import) > choose the file. The track will be revealed on the map and appear in 足跡 (Footprints). Then open 製圖 (Maps) to frame and share it.

4. Background location
Background location is the main feature: the app records the user's path while the phone is in a pocket. Recording starts only when the user taps the record button and stops when they tap it again. If it was on when the app closed, it resumes the next time the user opens the app. The system location indicator is always shown. The app still works if the user chooses "While Using" or denies location; they can import tracks instead.

5. External services
Map tiles: OpenFreeMap (OpenStreetMap data). Terrain tiles: AWS Open Data Terrain Tiles. Only tile requests are sent. The recorded path stays on the device. There is no developer server.

6. Regions
Functions are the same in all regions. District names, coverage by district, and offline region download currently cover Taiwan only.
```

## 十、卡住的時候

### 打包紅燈

先點進去看有沒有任何一步跑過。一步都沒跑、顯示 cancelled，是 GitHub 排不到機器，重跑就好。

| 訊息 | 原因 | 怎麼辦 |
|---|---|---|
| 少了 widget 的 profile secret | `IOS_WIDGET_PROFILE_BASE64` 沒放 | 照第三節放 |
| profile 是給 … 的，要的是 … | 兩個 profile 貼反 | 對調重放 |
| 沒有 App Group | App ID 沒勾，或勾了之後沒重做 profile | 第二節第 2、3 步重來 |
| MAC verification failed、匯不進 `.p12` | 密碼錯，或 `.p12` 的加密方式太新 | 先對密碼，再照建置說明用 `-legacy` 重新匯出 |
| The specified item already exists in the keychain | `.p12` 裡帶了 Apple 中繼憑證，人蔘修煉踩過 | 請 AI 在匯入那步把「已存在」當成過 |
| No signing certificate "Apple Distribution" found | 憑證過期，或 profile 選到另一張 | 重做憑證或 profile |
| 兩個 secret 都還原不出有效的 .p8 金鑰 | 內容少了一截，或貼到別的東西 | 用第三節的指令重放 |
| App Store Connect 不認這把金鑰（401） | Key ID、Issuer ID 跟 `.p8` 對不上，或金鑰撤銷了 | 三個從同一把金鑰重放 |
| 還沒有這個 App、No suitable application records | App Store Connect 還沒建 App | 第二節第 4 步 |
| SDK version issue | Xcode 太舊 | 第七節第 11 項 |
| 版號重複、不收這個版本 | 這個版本號已經通過審查 | 把版本號往上加 |

試三次還不行，把整段錯誤貼給 AI，先做別的。

### 被退

1. 先看 Apple 附的截圖和裝置型號，找審查員看到哪一頁
2. 要資料的（2.1）：補影片和備註，同一個 build 重送
3. 畫面上的字或程式有問題：改完出新 build
4. 用英文在被退那則訊息回：原因、哪個 build 修了、怎麼測
5. 記一筆到《多米 iOS 開發準則》的附錄 B
